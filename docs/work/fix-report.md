# 审查修复报告

## 已修复

### R1：明确保存的无认证配置在重启时被自动发现覆盖

- `electron/store.ts` 在加密存储中新增独立 `configured` 标记。初次生成是 `false`，手动保存/导入后是 `true`。
- `needsInitialDiscovery()` 仅由该标记决定；`electron/main.ts` 启动使用此判断，不再把认证来源 `none` 当成未设置。
- 兼容没有新字段的旧文件：已有认证来源或非默认地址/发行版视为已配置；未修改的初始默认配置仍允许发现。
- UI 在连接状态变化后重新读取公开设置，并用请求编号过滤过时结果；自动 WSL 导入后会显示最新来源和发行版。

### R2：手动密码认证无法从设置使用

- 添加 Token / Password 选择框，两种输入均遮蔽显示。
- 切换类型时清空当前输入，提交只包含所选类型，避免把旧 Token 一并提交。
- 密码首尾空格原样传递；Token 仍会去除首尾空格。保存成功清空输入；已有秘密从未返回 renderer。

### R3：不同网关的相同会话键复用旧记录

- 保存或导入成功后清除会话缓存、远端/本地列表和选择，创建新的空会话视图。
- 每次更换配置先递增工作区代际；列表、历史、发送确认、停止确认和停止后的历史刷新均检查所属代际。清空后旧异步结果无法重新写入。
- 连接状态报告未见过的新端点时也会清空旧作用域。配置已先切换时不重复清空，保留用户在新端点下新写的草稿。
- 设置页与 README 明确说明保存/导入会清空当前视图和未发送草稿，服务器记录仍从对应网关读取。

### 最小窗口输入区被挤出

- `workspace`、`session-sidebar`、`rail` 设置 `min-height: 0` 并限制溢出，让内部可滚动区域分配剩余高度。
- 在 Electron 最小外窗对应的 944×641 内容尺寸，发送按钮、composer footer 和侧栏底部均完整处于视口内。
