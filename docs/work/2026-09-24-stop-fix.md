# Stop 停止确认修复

## 原因与依据

本机安装的 OpenClaw `dist/chat-B1gaDaH9.js` 中，指定 `runId` 的 `chat.abort` 在未找到控制器时返回 `{ ok: true, aborted: false, runIds: [] }`。这表示运行 ID 未命中，不是等待中的确认。省略 `runId` 时，网关检查该会话的全部控制器；没有任务才返回上述空结果，权限不足则返回 RPC 错误。

原客户端把全部非 `aborted: true` 回执视为“网关尚未确认停止”，保留旧运行状态，后续点击仍请求同一个 ID。另有两处时序问题：发送尚未确认时就请求停止；停止成功后必须先成功读取历史才能释放运行状态。

## 修改

- 优先停止指定运行，明确未命中后只对同一会话回退一次。
- 网关明确确认已停止或会话已空闲时结束等待，随后刷新历史。
- 刷新历史失败时保留本地消息和部分回复，允许手动重试刷新。
- 发送回执前记录停止意图，收到实际运行 ID 后执行停止。
- 每个异步回执检查工作区代次与原始请求 ID，防止迟到结果影响新回复。
- 不把格式不完整的回执、RPC 错误或权限错误当成停止成功。
