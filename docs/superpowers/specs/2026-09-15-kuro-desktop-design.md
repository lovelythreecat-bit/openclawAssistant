# 库洛桌面工作台：第一版设计

用户已选择独立桌面界面、萌系二次元风格、角色名「库洛」，并于本轮要求继续实施。此文记录已确认的聊天方案，常规实现细节由开发代理推进。

## 目标与界面

Windows Electron 桌面应用连接 Ubuntu-24.04 WSL 中现有 OpenClaw 网关。樱花粉、奶油白、深色正文，圆角卡片、左侧导航、会话列表、主内容区。角色图用于欢迎页和头像。聊天、网关、设置三个页面。窗口最小 960×680，默认 1320×860。尊重减少动态效果的系统偏好。

## 行为

- 启动显示欢迎页，支持新会话、历史列表搜索、读取最近 200 条消息、继续聊天、流式回复、Markdown 和停止生成。
- 历史以网关为准，不在项目中存储真实聊天内容。不同会话的事件不能混入当前会话。
- 网关页显示真实的连接与认证状态、版本、端点和最近错误。首次启动尝试只读导入本机 WSL 配置并连接；后续使用明确保存的配置连接，不覆盖用户选择。提供手动连接、断开和重新连接；不自动启动、停止或修改 WSL 网关。
- 默认端点 ws://127.0.0.1:18789。第一版仅连接本机回环端点，以适应用户现有部署。
- 设置支持从指定 WSL 发行版导入 gateway.auth 中的 token/password，或手工填写凭据。凭据只在主进程中使用，通过 Electron safeStorage 加密保存；不返回给页面，不写日志。导入不修改原配置，不导入其他模型或渠道凭据。
- 使用独立 Ed25519 设备身份完成 protocol 3 challenge 握手，仅申请 operator.read/operator.write。遵守网关配对要求，不关闭认证、不复制其他客户端设备身份。
- 发送消息必须由用户操作触发；自动验证仅调用只读方法，真实发送测试需另行获得用户指示。
- 功能不可用时展示具体状态，不展示虚构会话或假在线数据。

## 边界与结构

Electron 主进程管理连接、身份、存储、WSL 只读导入。preload 暴露命名的受限 IPC 方法。renderer 无 Node 权限、不开启远程内容；窗口启用 contextIsolation 与 sandbox，禁止页面跳转及新窗口。外部链接仅允许 http/https 并由主进程打开。

GatewayClient 负责请求关联、超时、nonce 签名、断线清理、事件转发。React 状态负责当前会话与运行标识的隔离；会话切换时使旧异步响应失效。流式 delta 为完整快照，必须替换而非追加。

## 本轮交付与验证

可启动的桌面应用、角色素材、源码、开发脚本、连接说明和 Windows x64 便携 EXE。用户在夜间授权自主推进后，交付扩展为可直接运行的 Windows 产物。优先跑通真实连接与只读历史；在本地协议模拟服务器上验证发送、停止、认证失败及断线。运行 TypeScript 检查、构建、Node 协议测试、Electron 窗口烟测和截图检查。托盘、开机启动、多角色表情属于后续步骤。

## 实测后的协议修正

WebSocket 在 Electron 主进程运行，使用协议提供的通用客户端 `gateway-client`，mode 为 `ui`，并保留独立设备签名。早期 `webchat-ui/webchat` 声明被实际网关当作网页客户端，触发了浏览器 Origin 检查；原生应用不应使用这个声明。不伪造浏览器 Origin，不使用免设备的 backend 信任例外，不修改网关配置。
